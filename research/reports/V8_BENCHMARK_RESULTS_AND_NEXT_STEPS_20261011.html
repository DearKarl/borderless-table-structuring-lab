4. Execution and comparability

  • V8.1/seed0 and V8.2/seed0 each retain 161 empty technical failures caused by the PDF assembly defect. These are full-denominator execution results, not clean training-effect estimates.
  • All six model denominators remain 1651. Failed rows were not removed and no model was reselected using benchmark quality.
  • The three seed1 runs have zero inference failures and zero empty predictions. Their descriptive comparison does not establish statistical significance.
  • Two seeds per method, with two seed0 runs technically compromised, do not establish general cross-seed stability.
  • The shared native baseline is stronger on all three table metrics than every fine-tuned run. Absolute scores alone do not establish improvement.
  • These are local official-protocol benchmark results, not an external leaderboard submission.

5. V8.4 and V8.5: the next comparison

VersionInitializationShared interventionSeeds
V8.4Ordinary LoRAFull TDATR-style adapted training / supervision0 and 1
V8.5LoRA-GAThe same TDATR-style intervention0 and 1

Keep the same frozen dataset. Reuse the same 20,000 training tables, 11,217 sources and DEV split. Derive additional labels only from existing verified annotations. Audit row/column relations, empty cells, spanning cells and box-label coverage; record unavailable labels explicitly without silently changing the cohort.

  1. Diagnose on TRAIN / DEV first. Separate native detection/crop failures, text errors, row/column and span errors, and decoding errors. Also investigate why fine-tuning trails the matched native baseline. Do not select loss weights, checkpoints or design details using the exposed benchmark.
  2. Freeze the adaptation mapping. Specify which TDATR tasks, localization and alignment components are implemented, their losses, inference behavior and all deviations. With the existing backbone and dataset this is an adapted reproduction, not a claim of exact paper replication.
  3. Freeze a fair budget. Both new arms start from the same original base and use matched task schedules, seeds, checkpoint selection and evaluation. Multi-stage training may change exposure and compute relative to V8.1–V8.3; document that difference before execution instead of assuming comparability from an unchanged dataset.
  4. Reuse completed controls. Keep matched native, ordinary LoRA (V8.1), LoRA-GA (V8.2) and lightweight position supervision (V8.3). No automatic refitting of V8.1/V8.2. Their compromised seed0 evaluations remain qualified; any remediation needs its own explicit protocol.
  5. Define success before new runs. Make table TEDS the proposed primary endpoint; preserve structure TEDS, table edit, failures and cost as companion outcomes. V8.4 tests the complete intervention against ordinary LoRA; V8.5 versus V8.4 isolates GA within that intervention. Exceeding V8.3 alone does not establish improvement over the stronger native baseline.

The naming and unchanged-data principle are agreed. This report records the next design; it does not launch new experiments. Detailed error evidence, implementation coverage and the final exposure / compute protocol are still to be frozen. The existing confirmation set and full benchmark have now been exposed and must not be described as untouched tests for the next design.
